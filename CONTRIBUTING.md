# Contributing to RadioText AI

RadioText AI 0.2.0 Test is an early testing project. This public repository currently shares documentation only. Contributions are welcome by arrangement with the owner. Access to private project material or a test APK does not authorize reposting it, publishing recordings or redistributing signing material.

## Participation status

At present, contribute only non-personal documentation corrections. The roles and feedback template below describe future arranged work, not open enrollment. Wider testing and collection of personal feedback must wait for the operator/contact, lawful-basis, retention, recipients and rights-handling prerequisites in [PRIVACY.md](PRIVACY.md). Do not submit personal material publicly to request access.

Use original non-personal text or synthetic examples with documented rights. Do not copy broadcaster audio, transcripts, logos, rules or third-party code into contributions without an applicable right to share them. A contribution does not automatically assign copyright or create a new project license; the maintainer must agree on appropriate terms before accepting reusable material.

## Ways to help

| Participants | Useful contributions |
|---|---|
| Android developers | Review audio lifecycle, permissions, background behavior, release configuration and measured performance |
| Speech-recognition specialists | Design labelled RU/EN evaluations; document model provenance, WER/CER, exact keyword errors and confidence limits |
| QA testers | Reproduce device scenarios from [TESTING.md](TESTING.md), with exact versions and evidence |
| Accessibility specialists | Review TalkBack, focus, text scaling, contrast, touch targets and comprehension without sound |
| Deaf and hard-of-hearing users | Voluntarily describe reading needs and real interface difficulties; no diagnosis or hearing-loss proof is required |
| Volunteers | Improve documentation, validate official source references with permitted access, and organize redacted feedback |

## Agree on scope first

Use an owner-authorized private issue or contact route. If you cannot access it, ask the owner to provide one; no public reporting address is currently verified. Check existing documentation and history before repeating work. Propose a small, reviewable change and its necessary checks. Preserve working functions and user data. Keep fixture contests and synthetic keywords separate from production data.

For future code work, agree on access, architecture, applicable licensing and third-party notices with the maintainer first; application code and its notices are not distributed in this documentation-only repository. Do not add paid services, cloud audio processing, telemetry, new permissions or automatic participation without a separately reviewed decision. This documentation package itself changes no application code.

## Safe, voluntary testing

- Read [PRIVACY.md](PRIVACY.md), the [testing plan](TESTING.md) and the supplied artifact's signing/installation notes before opting in.
- Use a test device/profile where practical. Keep 0.1.9 installed when trying the separate preview package; do not uninstall it to bypass a signature mismatch.
- Start/stop listening deliberately. Use microphone or playback capture only where you have permission. Respect broadcaster, contest, geographic and platform restrictions.
- Prefer synthetic test material. Do not record, upload or share radio audio or other people's speech without separate authorization and any required consent.
- Testing never requires sending an SMS, making a call, paying for a ringback service, registering for a contest or supplying banking/identity documents. A simulated scenario is sufficient.
- Do not upload the private APK, source, logs or screenshots to a public scanner/forum or external service without the owner's specific permission and a privacy check.

## Feedback template

Provide only what is needed:

1. App label, version, package and APK SHA-256 if available.
2. Android version/API, device model and relevant caption/accessibility settings; no serial number or account ID.
3. Input mode, selected language and station/official URL if relevant.
4. Minimal steps, expected result, observed result and local time/timezone.
5. Reproducibility and impact: lost captions, wrong word, inaccessible control, crash, unexpected listening or suspected disclosure.
6. A short redacted text example or cropped screenshot if voluntarily provided. Label synthetic material clearly. Do not attach complete history or audio by default.

Remove phone numbers, email addresses, names of bystanders, private messages, credentials, verification codes, account/payment data and signed/private access URLs. Diagnostics can include device details or stream URLs; inspect them before sending. Do not attach personal material before the intake prerequisites are met. Any later permitted attachment needs agreed purposes, access and retention; permission to quote does not replace applicable legal obligations.

## Security reports and review

Send suspected vulnerabilities through an owner-approved private route, not a public issue, scanner share link or discussion. Report reproduction and potential impact without exploiting third-party accounts or accessing other users' data. No vulnerability disclosure response time or bug bounty is promised.

The maintainer reviews changes and recorded checks before integration. A successful host test is not Android acceptance; a passing synthetic example is not proof of real contest accuracy. Do not mark roadmap items complete without evidence. See [ROADMAP.md](ROADMAP.md) for current work. Request the relevant license and third-party notices before any separately authorized source or binary distribution.
